Does web search make AI agents better at real work?

When the job is about something recent, it decides the outcome: with no search, both agents passed 0% of those briefs; with any search provider, 71–95%.

See the results

What we found

From 609 graded runs of Claude Code and Codex.

  • 0% → 95%Search decides anything recentWith no search, both agents failed every brief about events after their training data. Every one of the 6 providers closed most of the gap.
  • A tieNo provider wins everywhereParallel led on Claude Code and Brave on Codex, and most ranges overlap.
  • 76% vs 90%On well-known topics, memory does most of the workAnswering from memory passed 76%; the best provider reached 90%, within the margin of error, using up to 4× the tokens.
  • 7%Agents still search with keywordsOnly 7% of searches read as plain questions. Runs did better when the original source showed up.
  • 4 APIsCalled directly, each search API led a different jobExa added the most new facts; Firecrawl read the most pages other tools could not.

Eight ideas behind every number on this site.

AgentSearch setupTraining cutoffBriefRunBlind grading95% rangeTie

Agent

The AI coding agent doing the job: Claude Code or Codex.

The agent and its model stay the same in every run of a test. Results belong to one agent: a ranking on one did not always hold on the other.

Search setup

The one thing that changes: a search provider, the agent's built-in search, or none.

Each provider is plugged in through its own official connector at default settings. Two controls frame them: no search at all, and the search the agent ships with.

Training cutoff

The date a model's knowledge ends.

Jobs about events after the cutoff cannot be answered from memory, so they show what search adds. Jobs with well-documented answers show what it adds when memory already knows.

Brief

A short research report that ends in a decision and cites its sources.

A brief passes with the right decision, at least 70% of the key facts and no more than a quarter of its claims unsupported by the pages it cites.

Run

One task with one search setup, repeated three times.

Every run starts in a fresh, sealed workspace, so nothing carries over. The tasks, limits and instructions are the same for every setup.

Blind grading

The grader never sees which setup produced the answer.

Automatic checks run where a task has them. Otherwise an AI judge compares the answer with the saved source pages, without knowing the provider.

95% range

Where the true score most likely sits.

A score from a few dozen runs is a measurement, not a fact. The range shows how far it could move if the test ran again.

Tie

Two ranges overlap, so the data cannot separate them.

When ranges overlap, the results say so instead of naming a winner. One place higher on a list is not proof of being better.

How to read these results

A narrow measurement: a fixed set of jobs on the agents and settings named, not a ranking of any provider or product as a whole. Different jobs, agents or settings can give a different order.

  • Every pass rate comes with its 95% range. When two ranges overlap, the data cannot separate them: the difference may be chance.
  • Each benchmark is a few dozen runs per setup on one or two agents, at default settings.
  • A note beside a number says what qualifies it. Tap it to read.

What we asked the agents to do

Real tasks from the benchmark, quoted from its task catalogs.

Research brief

Security releases the AI has never seen

Python shipped these security releases on March 3, 2026, after the AI models' training data ends. Without search, an agent can only guess. The source.

Read the task and how it is graded
As of March 10, 2026, research security maintenance for Python 3.10 through 3.12. Cover patch-release status, HTTP header validation, XML parsing and SSL memory safety. Produce a concise change-impact brief for maintainers without assuming they can upgrade minor versions. Return JSON with brief (markdown), claims (text and citation_urls).

The brief must reach the right decision, cover at least 70% of the key facts and keep unsupported claims to 25% or less, checked against the original source.

Research brief

A platform policy that just changed

GitHub changed what npm access tokens can do on July 31, 2026. The answer only exists in recent sources. The source.

Read the task and how it is graded
As of August 5, 2026, write a research brief on npm token security for maintainers whose automation both publishes packages and manages package access. Explain which operations their credentials can perform, any dated future commitments, and which GitHub credential types are in scope. Return JSON with brief (markdown), claims (text and citation_urls).

Same bar as every brief: right decision, key facts covered, few unsupported claims.

Code fix

Patch a security advisory in real code

The fix shipped in a library release after the cutoff. The agent has to find the advisory and the release that fixes it, then change the code. The source.

Read the task and how it is graded
Repair the session-token middleware: return claims for valid signed tokens and None for every rejected token. Use a dependency release that addresses the applicable advisory without weakening signature checks.

Hidden tests must pass in an isolated workspace. Weakening the security check to make them pass fails.

Documented knowledge

A well-documented technical question

This has been public for years and is probably in the AI's training data. It tests whether search adds anything beyond memory.

Read the task and how it is graded
Kubernetes v1.22 removed a batch of beta API versions and broke clients that still called them. Build the list of API groups whose beta version v1.22 removed. Report at least eight. For each, give the removed apiVersion, the replacement apiVersion clients must migrate to, and a primary-source URL from the Kubernetes deprecation guide or release notes. Also report the release in which the removals took effect.

The list must match the official release notes, scored by a grader that never sees which search provider was used.
