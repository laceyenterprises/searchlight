Searchlight

Glyphs

48 line glyphs on a 24 px grid: 2 px strokes, square ends, mitred joins and at most one accent, in Lacey blue. Each one at 48, 32, 24 and 16 px on the light and the dark ground.

The mark

Three options for the Searchlight mark, drawn on the glyph grid: ink plus one Lacey blue beam. Each must read at 16 px.

logo-lamp

Lamp and beam: the searchlight itself. A round lamp casts one wide Lacey blue beam up and to the right, toward what it finds.

logo-lens

Lens and beam: the search lens, lit. The beam leaves the lens like light from a lamp.

logo-tile

Tile: the lamp and beam on a solid ink tile, the boldest at favicon size.

Who is tested

The agent does the job; the search setup is the one thing that changes between runs.

agent

Agent: the AI coding agent doing the job (Claude Code, Codex)

provider

Search provider: the search service plugged into the agent

setup

Search setup: one way of giving the agent search; the only thing that changes between runs

built-in

Built-in search: the search the agent ships with

no-search

No search: the control run that answers from memory alone

model

Model: the AI model inside the agent, whose knowledge stops at a training cutoff

The job

What the agent is asked to do, and what it searches with.

brief

Brief: a short research report that ends in a decision and cites its sources

code-fix

Code fix: change real code so its hidden tests pass

cutoff

Training cutoff: the date the model's knowledge ends; Searchlight's jobs are about what came after

query

Query: what the agent typed into search

source

Source: the page a claim comes from

results-list

Search setup: hands back a list of results for the agent to read

answer

Research setup: hands back a written answer with its sources

Running it fairly

What keeps a comparison honest: the same job, a sealed workspace, repeats and a blind grader.

run

Run: one task, one search setup, one repetition, graded once

repeat

Repeat: every task runs three times per setup

sealed

Sealed workspace: a fresh, isolated workspace for every run

same-but-one

Change one thing: the agent, model and instructions stay fixed; only the search setup changes

blind

Blind grading: the grader never sees which setup produced the answer

judge

Judge: an AI model that checks each answer against its sources

pre-registered

Pre-registered: the questions and scoring rules were fixed before any result was seen

holdout

Holdout: questions kept back from tuning, so a result cannot be fitted to them

Grading

How an answer earns credit. Verified, unsupported and unverifiable are signals: their colour carries the meaning, and a word always goes with it.

verified

Verified: the claim was checked on the page it cites and holds up

unsupported

Unsupported: the cited page does not back the claim

unverifiable

Unverifiable: the cited page could not be read, so the claim was not credited

strict-credit

Strict credit: a provider earns a finding only if its own cited page supports it

insight

Insight: a verified finding that would change a decision, valued 1 to 3

unique

Unique: a finding only one provider earned

overlap

Overlap: findings two providers both earned

gap-closed

Gap closed: how far a setup got from the no-search score toward the answer-handed-over score

Reading the results

Ranks, ranges, ties and what a result cost.

ranking

Ranking: setups in order of their score

range

95% range: where the true score most likely sits

tie

Tie: two ranges overlap, so the test cannot separate them

tokens

Tokens: the units AI models bill by

cost

Cost: what a run or a study spent, in dollars

latency

Latency: how long a provider took to answer

caveat

Caveat: a note on what a number does and does not show

filter

Filter: narrow the view to one agent, provider or benchmark

The publication

Benchmarks, studies, reports and the pages that explain them.

benchmark

Benchmark: a fixed set of jobs, run on every search setup

study

Study: one fixed set of questions sent to every search and research service

report

Report: the published record of a benchmark or study, with its data

method

Methodology: how the tests are built, run and graded

walkthrough

How it works: a test, one step at a time

learn

Learn: the ideas behind the numbers, one at a time

open-source

Open: the tasks, the code and the data are published

contact

Contact: questions, corrections and result challenges

menu-close
